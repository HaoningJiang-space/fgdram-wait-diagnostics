# 1. FGDRAM 最小资源契约与参数出处

## 1.1 范围与证据等级

目标是检查一次请求何时因什么资源不能执行。代码为本轮从空目录新建的 Python 标准库模型；不是原作者模拟器，也没有借用某一代 HBM 的隐藏默认参数。

主要来源：[FGDRAM，MICRO 2017，DOI 10.1145/3123939.3124545](https://www.cs.utexas.edu/~skeckler/pubs/MICRO_2017_Fine_Grained_DRAM.pdf)。本地 PDF SHA-256：`844ade727a07f3af0b831f2d43821f2a33d9fdba95d84bdf1491d634bcd24ab9`。PDF 页码与正文页码均从 1 开始，Figure 7 在第 6 页，§3.3 跨第 7–8 页，Table 2 在第 10 页。PDF/全文提取只保存在本地 sources/，不随 Git 发布。

证据分三类：**原文给出**；**依据结构建立的抽象**；**尚未确定、显式赋值并做敏感性检查**。通过程序断言只说明遵守了这份契约，不能把第三类变成原文事实。

## 1.2 资源共享表

| 资源 | 共享范围及本轮规则 | 出处/限制 |
|---|---|---|
| 位线、局部感测与恢复状态 | 每个 `(grain,pseudobank)` 只有一个行状态；从 ACT 执行到 PRE 完成不能用它打开另一行 | 保守的单状态基线；未加入 SALP |
| 主字线/行选择 | 同一物理 bank 的四个 pseudobank，目标同一 subarray 时可同一行，不可不同行同时激活；已在途的 ACT 也参与冲突检查 | §3.2、§3.3、Figure 7；同一 bank 按两个 grain 组织 |
| 相邻 subarray 的感应放大器 | 不把同一 pseudobank 切片的相邻 subarray 视为独立；当前单状态约束已覆盖这一冲突，未声称额外并行能力 | [DreamRAM §III-B](https://arxiv.org/html/2512.12106v1) 描述 open-bitline 相邻共享；精确 FGDRAM 版图仍缺失 |
| 行命令传输 | 8 grain 共用；baseline 一条，C 两条；ACT/PRE 各自占用持续时间 | §3.3；ACT 精确长度未知 |
| bank 行译码器 | 同一 bank 的行命令执行间隔至少一个 2 ns 核心周期；C 不复制译码器 | 保守抽象，原文未给出精确吞吐；可检查独立区间 |
| 列命令传输 | 8 grain 一条，始终不增加；可与行命令同一时刻发送 | §3.3；READ 占 2 ns 为显式假设 |
| MAT→GSA/本地串行化路径 | 每 grain 每 16 ns 一个 32 B 原子；每次八个 2 ns 内部泵周期 | §3.2；不同 pseudobank 仍共享这一路径 |
| 返回槽位 | 每 grain 4 个原子；从 READ 开始发送到整个数据 burst 返回，预留一个槽位 | 有限队列假设；2 槽敏感性。预留策略会影响气泡 |
| 数据出口 | 每 grain 2 GB/s，每 32 B 占 16 ns。D 在相邻两个 grain 的缓冲之后选择两个既有出口 | §3.2–3.3；D 为零额外延迟的受限诊断理想化，不是已实现网络 |
| 激活记账 | 保留一个覆盖 128 grain/16 命令组的 die 域；滚动 12 ns 内最多 32 ACT。tRRD 默认按命令组为 2 ns | Table 2 给数值，作用范围未完整明确；范围是假设，保留替代运行 |
| 输入/请求容量 | 64 个未完成逻辑记录；256 个尚未返回的 32 B 原子。只有已释放、依赖已完成且容量允许的记录能入队 | 诊断驱动设定，不是实际 GPU 参数 |

主吞吐实验只驱动第一个 8-grain 组，其他 15 组**明确为空闲边界条件**。全 die 资源对象和激活规则没有删除；`all_grains_act` 另行驱动全部 128 grain 检查跨组约束。它仍不是其他组承载真实应用流量时的性能预测。

Table 2 的 `grains/bank` 行写 4，与 §3.2/Figure 7 的两个 grain、四个 pseudobank 表述不一致。本模型局部关系使用后者，并记录冲突，未把该表默认为已解决的完整产品拓扑。

## 1.3 时序与传输口径

| 参数 | 值 ns | 证据 |
|---|---:|---|
| tRC / tRCD / tRP / tRAS | 45 / 16 / 16 / 29 | Table 2 |
| tCL / tBURST / 同 grain READ 间隔 | 16 / 16 / 16 | Table 2 与 §3.3 |
| tRRD / 激活窗口 / 窗口计数 | 2 / 12 / 32 次 | Table 2；作用范围待外部核实 |
| ACT 命令占用 | 4；敏感性 6 | 原文只明确 >2 ns；两个值均是假设 |
| PRE、READ 命令占用 | 2 | 根据最短命令周期选择；没有完整命令编码证据 |
| READ 后保持行有效的时间 | max(16 ns 内部泵周期，假设 read-hold 16 ns)；敏感性 read-hold 24 ns | **不是论文给出的 tRTP**；源端读出/预充电细节仍需电路或作者模拟器校准 |
| 输出延迟 | READ 被接收后至少 max(tCL,source)=16 ns，随后占出口 16 ns | 原子级抽象，不解析每一拍的内部波形 |

命令事件同时记录开始传输时间和接收/执行时间。tRCD/tRC/tRRD 等在本模型以接收/执行时间为参考。可以在前一 PRE 的尾部发送 ACT，只要新 ACT 到达时 PRE 已完成；这保留了控制传输与阵列过程的重叠。完整 row address 如何分拍、时序规范从哪一拍起算，仍需外部校准。

读完当前可见队列中该行最后一个原子时，可以在最后 READ 附带自动预充电。PRE 开始时间必须晚于 ACT+tRAS 和最后内部读出/read-hold；等待 tRP 后才重新使用位线。显式 PRE 对照会占行命令带宽。控制器没有查看尚未进入有限窗口的未来索引，也没有冻结旧机器的命令。

本轮不建模写、刷新到达、ECC/CRC 开销、真实应用缓存/地址转换/计算、真实电流波形或热行为。短窗口内“无刷新到达”是边界条件；不能把中段吞吐称为长期稳态。`wire_payload_bytes` 只计数据载荷，`wire_ecc_crc_bytes=null`，不声称统计了线路上所有比特。原文 §3.4 的 ECC/CRC 方案不能被无声省略后称作完整复现。

## 1.4 地址、调度与账单

受控输入直接使用 `(grain,pseudobank,subarray,row,column)` 物理元组，不冒充真实模型索引重建。对编号 i：grain=i mod 8，lap=floor(i/8)，pb=lap mod 2，sa=2×(2×(grain mod 2)+pb)，row=floor(lap/2)，column=0。32/64 B 保持相同起始元组；row 容量按 256 B，记录不跨行。跨行输入显式拒绝，留给未来完整映射层。

调度按所有已可见候选操作检查多原因掩码；候选 ACT/PRE 去重；先 row hit READ，再必要 PRE，最后按记录编号发 ACT。共享资源仲裁造成的未选中单独计 `scheduler_arbitration`，不伪装成物理时序。有限窗口的生产者按编号顺序入队；串行负对照的下一记录必须等前一条返回。

`candidate-ns` 是候选操作等待采样量，不是总执行时间的互斥分摊。局部原因分开为 tRCD、tRAS、tRP、tRC、read-hold；另外记控制冲突、行列命令口、源端路径、返回槽、激活窗口/tRRD。多个原因可以同时成立。全程聚合；等待样本只截取前 4000 条，完整资源占用仍能从命令/事件轨迹检查。

账单给出 ACT/记录、READ/ACT 分布、实际载荷、命令接口和出口占用时间、完成延迟及有限队列峰值。能量/电流值明确未建模，不以 ACT 数或窗口令牌冒充焦耳/安培。

## 1.5 干预定义与 Gate

- C：一组增加一条等价行命令传输通路，保持共享译码器、列命令、阵列时序和供电规则。
- D：相邻一对既有输出之间允许选择，保持本地 MAT 源端能力。新增连线、mux、缓冲和时延未计价，故仅是诊断上界。
- A：**未定义、不运行**。需要先提供具体独立切片、可独立保持的行地址和局部控制、不可共享的感应/预充电边界以及必要改动。现有来源不足以让本项目认证这样的额外对象。

目前合法对照为 base/C/D/CD；A/CA/AD/CAD 在结果中标注未定义。不能把缺失结果记作零收益，也不能用 SALP 的理想状态数覆盖物理共享限制。

下一 Gate：补全命令编码、作用范围与 PRE/readout 时序，或取得能交叉验证的独立实现；之后再扩展记录宽度/并发扫描和真实索引。第一轮不进行 288 次扫描来放大尚未校准的假设。
