# P0 日志与独立检查边界

本文件只定义新增的证据关联，保持 `0270afa` 的行为、时序和额度契约。P1 的内部首段/末段解释、硬件校准及离线排程尚未实现；这里不是计划中的 `04-event-contract.md`。

## 1. 关联字段

`command_id` 从 1 递增，是一次运行内的发送编号，独立于事件队列编号。所有命令都有类型、目标 grain/pseudobank/subarray/row、`activation_id`、发送时间、接收时间、长度、命令组和通路编号。发送编号沿事件链传递，不改变调度排序。

| 发送 | 必须对应的事件 | 约束 |
|---|---|---|
| ACT | ACT_ACCEPT | 接收时刻等于发送加配置中的 ACT 长度；目标与激活编号一致 |
| RD | READ_ACCEPT → DATA_READY → DATA_START → DATA_END | 每个 `(rid, atom)` 唯一；携带同一命令编号、行上下文、列偏移和字节数 |
| 显式 PRE | PRE_START → PRE_END | PRE_START 等于 PRE 接收时刻，PRE_END 在其后 tRP |
| 带 `auto_precharge=true` 的 RD | 另有 PRE_START → PRE_END | 自动 PRE 使用该 RD 的编号；不虚构一条 PRE 命令或消耗行命令接口 |

显式 PRE 的 `rid` 是触发换行的请求，可能不属于被关闭的旧行；检查器校验 PRE 的实际行上下文，不强制它等于触发请求的地址。DATA_READY 之后旧行可以已经关闭，数据仍按原 READ 上下文核查，不要求它对应此刻打开的行。

列地址为请求的 `offset + atom * atom_bytes`；每个原子传送 `atom_bytes`。即使整个错误事件链内部一致，也必须匹配输入请求的列地址。

## 2. 独立额度重建

ADMIT 根据输入重新校验地址、大小、发布时间和依赖；每条记录隐含入队其所有原子，不额外制造入队延迟。

| 额度 | 占用 | 归还 |
|---|---|---|
| 未完成记录窗口 | ADMIT 加一 | 所有原子已返回的 COMPLETE 减一 |
| 原子请求额度 | ADMIT 加记录所需全部原子数 | 每次 DATA_END 减一 |
| 每 grain 返回预约额度 | RD 开始发送时加一 | 对应 DATA_END 减一 |

返回额度是预约，不是 DATA_READY 后真实缓冲占用。检查器输出重建的峰值，不读取模拟器峰值或等待计数；回归脚本才将二者相互核对。

日志按时间非递减排列，同时间按日志顺序处理。最后 DATA_END 写在 COMPLETE 前；二者时刻相等。资源区间采用半开区间，结束时刻可以接下一次占用。自动 PRE 的尾部清理允许晚于最后 COMPLETE，必须保留到 PRE_END。

## 3. 历史与证据边界

新检查器要求 `p0-v2` 关联字段（版本记在检查回执中）。缺少这些字段的历史轨迹被拒绝，不从缺失证据猜测命令身份，也不声称新检查器直接认证了原始旧日志。

`verify_p0.py` 在隔离目录运行原提交，首先核对原轨迹 SHA-256 与冻结 manifest；再比较新轨迹的全部旧字段。除将同时间 COMPLETE 放到最终 DATA_END 后之外，原事件顺序和时间必须不变；COMPLETE 序列单独逐项比较。所有非检查器统计和汇总 CSV 也必须相同。

`AuditError` 不依赖 Python 可关闭的 `assert`。六类漏洞及扩展破坏测试在普通和 `python -O` 下都执行。通过有限测试不表示检查器覆盖所有可能错误，也不验证公开资料未确定的器件时序、供电范围或物理结构。

此检查器验证合法性与守恒，不证明调度最优，也不强制重现贪心策略。未关闭且没有关闭意图的最终打开行是合法状态；已有关闭意图则必须有完整 PRE 链。
