# P3：逻辑地址、缓存与完成契约

本层叠加于 `legacy_0270afa`，不改变 ACT/RD/PRE、返回预约、源端/出口和供电规则。`Simulator.step()` 仅抽出原 `run()` 的一个时钟周期；原程序调用无回调，新输入在本周期返回处理后、物理入队前推进。回归必须保持原 30 组的命令安排与完成时间。

## 1. 四种不同的身份

- `Lookup.lid`：消费者请求一次完整字节范围，可未对齐、跨行，含 release 与前向依赖。
- `block`：32 B 对齐的物理地址；每个 lookup 对它只要求相交字节。
- `Request.rid`：一次未命中的完整 32 B 读取。重复在途块合并，多条 lookup 可以等待同一个 rid；缓存命中不生成 rid。
- `activation_id`：既有模型的一次开行，可能服务多个 rid、多个 lookup。

物理 Request 不跨行的旧规则保留。跨行由地址层分解，各 lookup 仅在全部片段到达后完成一次。

## 2. 地址与容量

固定示例拓扑：128 grain × 2 pseudobank × 32 subarray × 1024 行 × 256 B = 2 GiB。不是 FGDRAM 或 HBM 容量规范。低位到高位为 column(8)、grain(7)、pseudobank(1)、subarray(5)、row(10)。

`linear` 直接解码；`xor` 将 grain 的低三位异或 `(subarray XOR row)&7`，其余位不变；异或两次即可逆转。两种映射同容量、无复制。映射单元测试检查全域随机地址、边界及反向编码。

表的虚拟字节紧凑连续。分配单组时，虚拟页 v 放到物理页 `(v//8)*128+v%8`；全 die 分配时放到页 v。它们改变使用哪些物理页，不改变硬件。表不共享其他分配；只读，不含一致性/写回。

## 3. 在线生产者

配置声明逻辑窗口、每周期发出的记录数、每周期缓存块查询数、MSHR 数、缓存块数、命中延迟、批大小及消费间隔。输入先按顺序等待 release/依赖；下一批等待上一批全部完成和消费间隔。地址产生是显式理想化的查询能力，不含真实 CPU 指令执行。

冷启动、全相联 LRU、32 B 块。命中时更新 LRU，数据在声明延迟后可消费。未命中时分配一个 MSHR；重复块加入等待者；填充发生于物理 DATA_END/COMPLETE 后。同时间先处理全部物理返回，再按返回顺序填充，再处理命中完成，然后产生新请求。新 miss 同时受 MSHR 和包含未入队请求在内的物理队列额度限制。缓存命中数据被取出后，后续缓存淘汰不取消已安排的命中返回。

一条较大 lookup 可以逐块发出，不要求一次占齐全部物理额度。有限窗口内未处理的片段留在生产者；控制器不能看到未来批次。不同结构的返回改变后续缓存状态、合并和批次到达，必须分别生成请求和命令。

## 4. 独立检查

`frontend_audit.py` 不调用前端拆分、调度或缓存辅助函数。逐字节重建必要覆盖，逐事件核对 admission、cache hit/miss/merge、MSHR、fill、片段返回、lookup 完成及批次依赖；独立计算 LRU、各窗口与 issue 限制。全部物理事件仍通过原 `audit.py`。

`L_ACCESS` 关联 `(lid, block, [lo,hi), rid, route)`；`L_FILL` 必须对应已经完整返回的 rid；`L_PART` 必须在返回/命中延迟满足后覆盖原范围；`L_COMPLETE` 必须等于最后片段时刻。无漏片、重复完成、提前数据、虚假缓存命中或超过额度。

## 5. 统计口径

`logical_requested_bytes` 是消费者请求量，可能包含重复。`wire_payload_bytes` 是实际 DRAM READ 数 ×32 B。`useful_dram_bytes` 对每个物理 rid 的 miss/merge 消费者字节取并集，再对 rid 求和；不会把多个消费者复用或缓存命中重复算入 DRAM 有用字节，也不计反量化扩展。再次读取同一地址是另一次物理服务，允许另计。

ACT/lookup 分母为逻辑 lookup，READ/ACT 来自实际激活编号。行命中和冲突来自实际命令与候选掩码，不能由记录宽度推断。等待计数可重叠，不归一化为 100%。组负载、队列峰值和供给不足单独报告；较大生产者窗口也不是“保证饱和”。

## 6. 边界

前端并非已校准 CPU/GPU、真实缓存层级、数值推理或生产服务。缓存查询/消费者回传不占 FGDRAM 出口；其开销只有声明的 query 宽度与 hit 延迟。没有数据值/模型精度验证，也没有数值计算收益。真实编号转换得到的是模型生成访问，不是机器采集的内存 trace。P3 的目标是检验先前动机是否仍成立，包括得到否定结果。
